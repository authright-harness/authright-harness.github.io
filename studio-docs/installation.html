Installation

Install AuthRight CLI, AuthRight Studio, or both. The two packages publish at the same version. Pick a mode below before the CLI-only package-manager recipes.

Prerequisites

You need Node.js 20.19.0 or newer. CLI and Studio both run on Node.

If that prints v20.19 or higher, you're set. If not, install a newer Node from nodejs.org or your version manager (nvm, fnm, asdf, volta).

The CLI path also uses an AI coding tool. AuthRight ships delivery for Cursor, Codex, and Claude Code (see Agents). Studio does not require one.

The CLI runs on Node.js. The application you analyze does not have to: Java and Node.js / TypeScript have the strongest coverage today; Python and Go are supported and being strengthened. More languages and stacks will follow. See Concepts.

Install modes

@authright/cli and @authright/studio publish together at the same version. There is no registry package @authright/core (the engine is embedded into each app tarball).

AuthRight Studio

A Studio-only install uses authright-studio and does not require @authright/cli. The commands do not take provider, API key, or cases-directory flags.

See AuthRight Studio. Coding-agent delivery is unchanged if you never install Studio.

Package managers

These recipes install CLI-only. Choosing a global installer is independent of how your application repo manages dependencies. For Studio, use the mode table above.

npm (primary)

pnpm

If pnpm reports that its global bin directory is missing, run pnpm setup, restart your shell, then retry.

yarn (Classic / 1.x)

Yarn Berry removed global add. On those versions, use npm, pnpm, or bun for the global CLI instead.

bun

Bun can install the package, but the CLI still runs on Node.js—keep Node 20+ on your PATH.

Verify installation

If the command is not found, the package manager's global bin directory is missing from this shell's PATH. Add that directory (or fix your Node version manager shims), then verify again. Do not treat cloning this repository as the install path.

Updating

Upgrade the global package(s) you use, keeping CLI and Studio on the same version when both are installed. Then refresh generated agent files in each project that uses the CLI:

authright update regenerates managed Cursor/Codex skills and commands for the tools configured in that project.

Uninstalling

There is no authright uninstall command. Removing AuthRight Harness is manual and does not rewrite your application source.

1. Remove the global package(s):

2. Optional — remove project artifacts. Delete .authright/ if you no longer want AuthRight Harness data for that repo. Keep it in git if you still need the decision history.

3. Optional — remove generated agent files. Delete Cursor auth-* commands / authright-* skills and Codex authright-* skills for tools you configured. See Agents.

Next steps

Studio. Open AuthRight Studio, then send your first ask or click New Case. You do not run authright init.

CLI. Initialize AuthRight in your project for the AI coding agent you are using. Most people work in one agent at a time.

Interactive: omit --tools. The CLI prompts you to select Cursor, Codex, or Claude Code. Detected host directories are pre-selected on first run.

In CI or any non-interactive shell, omitting --tools installs hosts detected from the project (for example .cursor/). Pass --tools none when you only want .authright/ with no agent files.

Specify the agent: pass --tools when you already know which one you are in.

Principles

What AuthRight Harness is is the product idea. This page is how that idea shows up in Studio: you lock one IAM ask in the browser, without the CLI, a coding agent, or OpenSpec.

Models

Studio calls a model only after you save a profile in Settings → Models. The command line does not set the provider or the API key, and Studio does not read provider keys from the environment.
