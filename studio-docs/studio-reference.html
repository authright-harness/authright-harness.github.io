AuthRight Studio reference

AuthRight Studio reference

Configuration, Case layout, and the local HTTP API. To install and open a first Case, start with AuthRight Studio.

Configuration

Models, API keys, and the HTTP proxy are configured only in the web UI (Settings → Models and Settings → Proxy) and saved in ~/.authright/studio/config.yaml. The command line does not set them, and Studio does not read provider API keys from the environment.

Studio stores named model profiles (provider + model + optional key/baseUrl). One profile is active for the next chat generation. Manage profiles and the Studio-global HTTP proxy from the left-rail Settings control (opens a preferences-style dialog with Models and Proxy). Switch the active ready profile from the Model control in the chat composer (next to Send)—the left rail does not repeat the active model label.

Legacy flat provider / model files migrate once to version: 2 on load. With no saved ready profile, Studio stays on the first-run setup screen until you save one in Settings.

Global config file

Path: ~/.authright/studio/config.yaml

(Same tree as Case folders: ~/.authright/studio/cases/ on disk.)

Cases and disk layout

A Case is one IAM Decide container: a local folder plus a bound chat thread.

Creating a Case creates:

  1. A folder under the cases root (default ~/.authright/studio/cases/<id>-<slug>/)
  2. A chat thread bound to that Case

All AuthRight I/O for that Case uses the Case folder as cwd. Artifacts live only under that folder’s .authright/.

Metadata store: ~/.authright/studio/cases.json (alongside cases/). On first start, Studio migrates legacy tasks/ + tasks.json into cases/ + cases.json when present.

Chat continuity is local-first: Mastra Memory (LibSQL file DB) keeps the last ~30 turns in agent context for the Case threadId, and Studio hydrates the chat UI from GET /api/cases/:id/history on open/restart. Deleting a Case (Delete in the Cases-rail ⋯ menu, or DELETE /api/cases/:id) removes that Case’s metadata row, folder, Memory thread/messages, and UI store rows. .authright/ on disk remains the source of truth for Decide artifacts while the Case exists.

Cases HTTP API (local Studio only)

MethodPathRole
GET/api/casesList Cases (title, titleSource, pinned, …)
POST/api/casesCreate Case ({ "title" } optional; UI sends IAM Decide)
GET/api/cases/:idOne Case
PATCH/api/cases/:id{ "title"? } and/or { "pinned"? }
DELETE/api/cases/:idFull Case cleanup (folder + Memory thread + UI stores + metadata)
GET/api/cases/:id/historyChat messages + progress for reopen

Studio tools confine writes to .authright/ and refuse CLI-owned lock files (decisions.yaml, auto-plan.yaml, status.yaml, …). Durable plan locks go through --set / --confirm-plan / --ready.

First-run / model gate

Until a provider + model + API key are configured (modelConfigured):

  • With no Cases yet, Studio uses a focused first-run layout: Cases / Activity side panels are hidden (no topbar), and a single setup hero owns the Configure model CTA.
  • With existing Cases, the three-column workbench returns; chat stays gated until a model is configured.

After a successful save that unlocks the model, Studio toasts “Model ready” and restores the normal Cases workbench. When the model is ready and you still have zero Cases, that workbench shows the zero-Case welcome + composer in the center (not the focused setup hero).

Settings dialog and chat switcher

  • Left-rail footer Settings opens a preferences-style dialog (not a drawer) with sidebar categories Models | Proxy.
  • Models: profile library (add / edit / delete / Test connection / Save). It does not show the active model name (that lives in the chat composer).
  • Proxy: Studio-global httpProxyEnabled + httpProxyUrl for outbound LLM provider calls from the Studio server (not browser→Studio). Save via PATCH /api/llm/proxy. Public status returns enablement + a redacted host:port display—never proxy passwords.
  • In an open Case, the chat input control row has a compact Model picker next to Send; it lists ready profiles and switches activeProfileId for the next turn (does not cancel an in-flight turn). Manage models… opens Settings on Models.
  • Curated model dropdowns per provider (with Custom model id…). openai-compatible uses free-text model id + required Base URL.
  • API key is write-only: leave blank to keep the existing env/file key. GET /api/llm / /api/health never return key values—only apiKeyConfigured, per-profile ready flags, sources, and non-secret proxy fields.
  • Test connection probes draft model settings without saving (and may send draft proxy fields). Success shows Connection verified.
