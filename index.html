The gap

Agents ship auth code. They rarely hold the decision.

Brownfield identity work fails when a coding agent invents an IdP, replaces AuthService, or skips mapping rules. AuthRight is the decision layer that sits upstream of implementation—so Cursor and Codex reason against constitution and contract, not vibes.

How it works

One loop. Three commitments.

Keep identity intent inspectable before OpenSpec writes the apply path.

  1. 01

    Understand

    Scan the repository for identity signals—services, tokens, federation hints—and capture what is known versus unknown in a durable context.

  2. 02

    Decide

    Structure Auth Changes against a project constitution. Record accepted decisions and contracts before any implementation plan is written.

  3. 03

    Verify

    After OpenSpec implements, review decision compliance, contract evidence, and scope boundaries—without AuthRight mutating application source.

Boundaries

Peer to OpenSpec—not a replacement.

AuthRight exports a structured change into OpenSpec. It does not run openspec apply, and it does not rewrite your application sources during review.

AuthRight owns

  • IAM discovery and context
  • Constitution and decisions
  • Auth contracts and review

OpenSpec owns

  • Proposal, design, and tasks
  • Capability specs and apply
  • Implementation change control

Agents own

  • Code under OpenSpec apply
  • Cursor /auth-* workflows
  • Codex $authright-* skills
