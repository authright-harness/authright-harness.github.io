AuthRight Harnessv0.5.6

Lock IAM decisions before agents write auth code.

AuthRight is the identity-security decision layer between a vague product ask and implementation. Use the CLI with your coding agent, or Studio in the browser—same engine, same version.

Use the CLIUse Studio

Real product asks

Vague identity prompts become locked decisions.

You do not need IAM vocabulary first. Describe what the product needs—then lock the design before anyone builds.

  1. 01Copy a product
    “Look at that well-known product we use every day—copy the same login, orgs, invites, roles, and SSO. Make ours feel the same.”

    Jump to code

    Agents mirror screens and start coding. What’s a must-have vs nice-to-have, how orgs and roles really work, and what “same” means stay fuzzy.

    With AuthRight Harness

    The reference becomes a checklist of decisions—accounts, tenants, invites, roles, SSO—not a UI to paste. You lock the model before anyone builds.

  2. 02Add enterprise SSO
    “We already ship email/password. Big customers want company SSO. Keep self-serve signup for everyone else—don’t break existing users.”

    Jump to code

    SSO gets bolted onto the same login path. Account linking, which users must use SSO, and who owns the org stay undecided until production breaks.

    With AuthRight Harness

    Password vs SSO paths, join rules, and tenant policy are decided first. Existing accounts stay usable while enterprise can turn SSO on.

  3. 03Swap the IdP
    “We’re on Keycloak today. Leadership wants OpenAM instead—same login, SSO, and roles for users. Don’t break the apps that already trust us.”

    Jump to code

    Agents rip out the old SDK and paste a new one. Token shape, logout, brokered IdPs, and what “same roles” means stay undefined until cutover fails.

    With AuthRight Harness

    The swap becomes a decided migration: what must stay equivalent, what can change, protocols and session rules, and a technology choice you can defend—then agents implement against that lock.

  4. 04Diagnose the code
    “Before we redesign anything—what’s actually open in this repo? Which APIs skip login? Where can someone reach data they shouldn’t?”

    Jump to code

    A chat skim of a few files. No shared report, weak file pointers, and the team argues from memory instead of evidence.

    With AuthRight Harness

    On the CLI, a diagnosis reads the app source and writes a shareable risk report. Decide comes after you know what’s broken.

  5. 05IAM as source of truth
    “Here’s what the product must do for login, orgs, and permissions. Make that the source of truth—not a slide deck, not a thread that goes stale.”

    Jump to code

    Requirements live in docs and chat. Agents invent auth as they go. Six months later nobody knows which rules are still real.

    With AuthRight Harness

    Your ask becomes a locked IAM source of truth—accepted decisions and contracts agents must follow. Later changes append or supersede; they don’t silently rewrite the model.

Two surfaces

CLI and Studio are peers.

Pick where you work. The Decide engine is shared. The closed loop is not: only the CLI completes scan → match → handoff → review.

  • CLI

    In your editor

    You already use Cursor, Claude Code, or Codex.

    LoopUnderstand → Decide → Request match → Handoff → Verify

    • Scan what identity already looks like in the repo
    • Decide with explore (HITL) or change (auto-plan)
    • Confirm the locked plan still matches the ask
    • Hand off to OpenSpec or Plan mode
    • Review after agents implement
    • Diagnose open routes and permission risks anytime

    ArtifactsRepository `.authright/`

  • Studio

    In the browser

    You want Decide without a coding agent.

    LoopOpen a Case → auto-plan Decide → IAM source of truth

    • Run a local web host (`authright-studio`)
    • Configure models in Settings
    • Create a Case and decide in chat
    • Lock auto-plan choices into Case files
    • Write an IAM source-of-truth document

    Studio does not scan, explore, diagnose, request-match, hand off, or review. Use the CLI for that loop.

    Artifacts`~/.authright/studio/cases/`

Why it exists

Coding agents invent auth when the design is still chat.

AuthRight sits upstream of OpenSpec and Plan mode. You lock architecture and technology choices first; agents implement against that package.
