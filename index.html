Core principle

Decision before implementation.

AuthRight Harness is not a competitor to coding agents. It is the upstream IAM decision layer: how should this project's identity be designed, why, and which technology—before anyone writes auth code.

Product interaction

Named commands for greenfield and brownfield.

Greenfield starts with /auth:explore. Brownfield uses /auth:scan, /auth:change, and /auth:doctor. After implementation, verify with /auth:review. Decided work hands off via the OpenSpec peer bridge /auth:to-openspec.

  1. /auth:explore
    01

    Greenfield — explore & decide

    Start exploring and defining a new IAM solution. A plain product ask becomes a Clarification Set, then architecture and technology decisions—ending in an Auth Decision Package.

    FlowClarification → Architecture → Technology → Auth Decision Package

  2. /auth:scan→/auth:change
    02

    Brownfield — scan & change

    Discover what identity already exists in the repo, then open a structured Auth Change against that baseline—so decisions stay grounded in the current system, not a blank slate.

    FlowRepo signals → Auth Change → Clarification & decisions

  3. /auth:doctor
    03

    Diagnose — doctor

    Assess the current repo’s identity posture and surface concrete optimization or upgrade recommendations—before you commit to a change path.

    FlowRepo diagnosis → Risks & gaps → Optimization / upgrade advice

  4. /auth:review
    04

    Verify — review

    After implementation, check that coding agents and OpenSpec work still match the locked Auth Decision Package—Decision Lock, not vibes.

    FlowImplemented change → Contract & decision checks → Review report

  5. /auth:to-openspec
    05

    Hand off to engineering

    Convert the decided package into an engineering proposal. OpenSpec and coding agents own implementation from there. This is the OpenSpec peer bridge—not one of the five user-intent commands.

    FlowAuth Decision Package → OpenSpec → Coding Agent

Core output

The Auth Decision Package—IAM designed, not merely described.

AuthRight Harness owns analysis, architecture, and technology selection. OpenSpec and coding agents own proposals, apply, and code. The handoff is a verifiable decision package—not another chat transcript.

  • Package contents — requirements, clarifications, architecture, technology, protocols, identity & authorization models, contracts, alternatives, and verification criteria.
  • Vendor-neutral — Keycloak, Auth0, Entra, Ory, and custom IAM are evaluated against your context, not sold as the default.
  • Evidence-based — every major choice stays explainable: requirement → evidence → analysis → decision.
