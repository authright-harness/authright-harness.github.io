Workflows

Common patterns using the design user-intent commands (colon product names). In Cursor type hyphen forms (/auth-scan); in Claude Code type colon forms (/auth:scan); in Codex type $authright-scan. Greenfield and brownfield are paths, not slash commands.

Dual Decide: /auth:explore is interaction HITL Decide (Shape, Agenda native HITL; recommended labeled not defaulted). /auth:change is auto-plan Decide (skip Shape HITL, full plan of resolved/unresolved, batch --set, confirm-plan → ready → request-match → export). Either path may be used on greenfield or brownfield.

Chat skills /auth:explore, /auth:change, and /auth:doctor run their CLI loop when the opening utterance matches that command or the invoke has no extra text. A mismatched opening line is answered in chat and does not create an Auth Change. The agent may hint another /auth: command (including the other Decide intent); it must not auto-switch slash/skill. Later questions in an already-started change are digression — do not abandon that change. This gate does not apply to /auth:to-openspec.

Happy path (greenfield) — HITL via explore

Use this when you want interactive option walking: new product, no identity estate yet, or the approach is not locked. /auth:explore asks Shape option questions before allocating AUTH-YYYY-NNNN and must not mark decisions accepted from the option answer alone. After required Shape chooses are answered, Decide continues in the same session. /auth:to-openspec intercepts unfinished work instead of bouncing away when a gap is already actionable.

Diagnose

/auth:doctor / authright doctor when you need risk findings (requires a prior scan). Findings are observations, not Gaps. Host agents may persist .authright/findings/agent-diagnosis.md. Overlays are inferences, not Decision Lock.

Document

/auth:doc (Cursor /auth-doc, Codex $authright-doc) writes an IAM document from the records already on disk. It does not update decisions, Design, or application configuration, and it has no terminal authright doc command.

What not to do

  • Don't invent /auth:greenfield / /auth:brownfield / /auth:engineering slash commands
  • Don't ask Keep current style / Centralize IAM during /auth:scan
  • Don't treat /auth:to-openspec as a user-intent equal to scan/explore/change/doctor/review/request-match
  • Don't treat /auth:doc as applying a solution or updating configuration
  • Don't bounce from /auth:to-openspec to explore/change when a gap is already actionable
  • Don't auto-run /auth:doctor because a Decide opening utterance looked like diagnosis (hint after chat is fine)
  • Don't use Agenda next as the primary UX on /auth:change auto-plan
  • Don't type product slash commands in the terminal—How commands work

Scan (or empty) then /auth:to-openspec with nothing in flight: hint /auth:explore or /auth:change. Export waits for an explicit continue confirm when nothing is pending — --ready is not silent.

How commands work

The one thing to know: AuthRight Harness has two kinds of commands, and they run in two different places.

Existing projects

AuthRight Harness is built for brownfield IAM: mixed IdPs, legacy sessions, partial OIDC, framework security that grew over years. You do not document the entire identity estate before the first useful change.
