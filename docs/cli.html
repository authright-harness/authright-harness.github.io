CLI reference

Terminal reference for the authright binary from @authright/cli. Product slash commands live on the Commands page.

Install: Installation. Chat orientation: How commands work.

Global option: --path <dir> selects the project root.

Thin closed loop

Inspect anytime: authright change (list) or authright change <id> (optional --json).

Terminal commands

CommandPurpose
authright init [path] --tools cursor,codex,claude|noneCreate .authright/ + agent delivery
authright updateRegenerate managed skills/commands
authright scanHeuristic IAM discovery → context.yaml (+ evidence / hypotheses)
authright explore [intent…]Structured exploration (options.yaml) under .authright/explorations/
authright changeList Auth Changes (replaces removed bare status)
authright change -- <intent> / change [intent…]Create DRAFT (may refresh context via scan)
authright change <id>Status for one change
authright change <id> --analyzeFill analysis.md → ANALYZED (may refresh context)
authright change <id> --readyLock DECIDED when Decision Package is export-ready
authright doctorStructured findings under .authright/findings/ (needs scan first)
authright to-openspec <id> [--slug] [--force]Export handoff to OpenSpec
authright review <id>Heuristic verify from EXPORTED

Hidden/advanced (callable, omitted from primary --help): authright validate, authright transition.

Also: authright --version, authright --help.

Exit codes: 0 ok, 1 validation/lifecycle, 2 unexpected.

Notes

  • There is no public authright analyze or authright status — use change --analyze / change / change <id>
  • There is no authright decide — edit decisions.yaml, then change <id> --ready
  • change <id> extra words is rejected (avoids accidental create); use change -- <intent> to create
  • explore / doctor treat init template context as unscanned until scan writes signals or scanned_at
  • doctor fails with a scan hint when context was never scanned
  • Targeted context refresh (on create/--analyze) merges into existing signals; it does not wipe a prior full scan
  • --ready rejects TBD verification placeholders; see Editing changes
  • to-openspec fails if the target OpenSpec folder already exists unless --force
  • init --force overwrites context/constitution only after confirm (or AUTHRIGHT_FORCE=1 non-interactive)
  • AuthRight Harness does not install or invoke OpenSpec for you — OpenSpec
